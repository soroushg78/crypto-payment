راهنمای جامع تعامل بک‌اند Go با سرویس‌ها و نودهای بلاکچینی خارجی

این سند تشریح می‌کند که سرویس درگاه پرداخت غیرحضانتی کریپتو چگونه بدون استفاده از گیت‌وی‌های واسط شخص ثالث (مانند NowPayments یا BitPay)، مستقیماً از طریق پکیج‌های اختصاصی واقع در پوشه backend/pkg با نودهای بلاکچین و وب‌سرویس‌های مالی جهت تبدیل ارز، پایش واریزها، تخمین کارمزد و سوئیپ دارایی‌ها تبادل داده می‌نماید.

Step 01 • Oracle
استعلام نرخ زنده ارزها
اوراکل والکس نرخ زنده BNB و گرام را هر ۴۵ ثانیه کش کرده و مبلغ معادل فاکتور را محاسبه می‌کند.
Step 02 • Derivation
تولید آدرس اختصاصی
موتور BIP-44 برای هر مشتری آدرس ایزوله BSC تولید کرده و برای TON یک شناسه مموی یکتا ایجاد می‌نماید.
Step 03 • Observer
رصد آنچین هر ۱۰ ثانیه
ناظر پس‌زمینه با متدهای JSON-RPC نود BSC و Toncenter تراکنش‌های ورودی را کشف و فاکتور را تسویه می‌کند.
Step 04 • Sweeper
سوئیپ به خزانه سرد
در صورت نیاز، ولت مستر به والت مشتری BNB تزریق کرده (Gas Station) و دارایی را به خزانه منتقل می‌کند.

اوراکل قیمت صرافی والکس (Wallex Price Oracle)

پکیج منبع: backend/pkg/wallex/client.go
پکیج والکس مسئولیت استعلام نرخ برابری رمزارزها با دلار آمریکا را بر عهده دارد. هنگام درخواست کاربر جهت پرداخت سفارش دلاری (مثلاً ۱۵ دلار)، این سرویس ارزش دلاری را به دقیق‌ترین مقدار رمزارز در همان لحظه تبدیل می‌کند.
آدرس سرور پایه (Base URL): https://api.wallex.ir
نوع دسترسی (Authentication): عمومی بدون توکن (Public API)
مدت‌زمان کش در حافظه (TTL): 45 Seconds (sync.RWMutex)
حداکثر مهلت پاسخ (Timeout): 6 Seconds
متد اندپوینت فراخوانی‌شده هدف و نحوه استفاده در بک‌اند خروجی و تبدیل
GET /v1/currencies/stats?key=BNB دریافت قیمت زنده دلاری بایننس‌کوین جهت محاسبه مقدار بایننس‌کوین واریزی فاکتورهای شبکه BSC. amount_usd / price
GET /v1/currencies/stats?key=GRAM استعلام زنده نرخ دلاری ارز گرام (کوین رسمی شبکه TON) جهت محاسبه تعداد ارز موردنیاز فاکتور. amount_usd / price
FIXED 1.00 USD (Hardcoded) تتر (USDT) در منطق سیستم استیبل‌کوین همگام با دلار بوده و نرخ آن به صورت ثابت ۱.۰ لحاظ می‌شود. amount_usd * 1.0
منطق کش درون‌حافظه‌ای و نرخ‌های اضطراری در فایل wallex/client.go Go Implementation
// ۱. ابتدا کش رم را بررسی می‌کند تا از ارسال درخواست‌های اضافی جلوگیری شود c.cacheMu.RLock() cached, found := c.cache[sym] c.cacheMu.RUnlock() if found && time.Since(cached.UpdatedAt) < c.cacheTTL && cached.Price > 0 { return cached.Price, nil } // ۲. در صورت قطع شبکه والکس، نرخ‌های اضطراری فال‌بک صادر می‌شوند تا کاربر معطل نماند: func (c *Client) getFallbackPrice(sym string) float64 { switch sym { case "BNB": return 600.0 // ۶۰۰ دلار پشتیبان case "GRAM": return 5.20 // ۵.۲ دلار پشتیبان default: return 1.0 } }

نود بلاکچین بایننس اسمارت‌چین (BSC Node JSON-RPC)

پکیج منبع: backend/pkg/bscrpc/client.go
پکیج bscrpc یک کلاینت اختصاصی و سطح‌پایین JSON-RPC 2.0 برای تعامل مستقیم با نود ولیدیتور زنجیره BNB Smart Chain است. این پکیج با حذف هرگونه وابستگی واسطه‌ای، تمام عملیات خواندن مانده، تخمین کارمزد، سوخت‌رسانی و سوئیپ دارایی‌ها را با فراخوانی توابع رمزارزی استاندارد اتریوم/بایننس اجرا می‌نماید.
آدرس نود پیش‌فرض (RPC URL): https://bsc-dataseed.binance.org
شناسه شبکه بایننس (Chain ID): 56 (BSC Mainnet)
آدرس اسمارت‌کانترکت تتر (USDT): 0x55d398326f99059fF775485246999027B3197955
آدرس والت مستر خزانه (Treasury): 0x742d35Cc6634C0532925a3b844Bc454e4438f44e
پروتکل متد نود (JSON-RPC Method) علت استفاده و کارکرد دقیق در سیستم پارامترهای ارسالی
RPC 2.0 eth_getBalance استعلام مانده کوین اصلی BNB در آدرس مشتری و والت تنخواه سوخت‌رسان مستر (Index 0). ["0x...", "latest"]
RPC 2.0 eth_call (balanceOf) فراخوانی سلکتور 0x70a08231 روی کانترکت تتر جهت دریافت مانده توکن‌های BEP-20 واریزشده. [{"to": USDT, "data": "..."}, "latest"]
RPC 2.0 eth_gasPrice استعلام زنده نرخ بازار کارمزد از ولیدیتورهای نود در قالب Gwei برای برآورد هزینه انتقال. []
RPC 2.0 eth_getTransactionCount دریافت نانس پندینگ (Pending Nonce) برای مرتب‌سازی تراکنش‌ها و جلوگیری از خطای Replay Attack. ["0x...", "pending"]
RPC 2.0 eth_estimateGas تخمین داینامیک واحدهای گس موردنیاز (۲۱,۰۰۰ واحد برای BNB و حدود ۶۵,۰۰۰ واحد برای انتقال تتر). [{"from":"...","to":"..."}]
RPC 2.0 eth_sendRawTransaction برادکست مستقیم تراکنش‌های امضاشده سوخت‌رسانی خودکار و سوئیپ دارایی‌ها به سمت بلاکچین بایننس. ["0x_RAW_HEX_TX"]

نود شبکه تون (TON Network - Toncenter API v2)

پکیج منبع: backend/pkg/tonrpc/client.go
پکیج tonrpc با نود مرکزی شبکه TON از طریق وب‌سرویس Toncenter API v2 ارتباط برقرار می‌کند. معماری شبکه TON در این درگاه به شکل «خزانه‌داری متمرکز» پیاده شده است؛ یعنی تمام مشتریان به یک والت خزانه‌داری واحد واریز کرده و با مموی اختصاصی (Memo / Comment) تفکیک و تسویه می‌شوند.
آدرس سرویس نود (Base URL): https://toncenter.com/api/v2
والت خزانه‌داری متمرکز TON: تنظیم‌شده در متغیر TON_TREASURY_WALLET
بافر زمانی مجاز برای خطای کلاک: -10 Minutes Buffer
آستانه پذیرش مبلغ فاکتور: 98% Threshold (جلوگیری از خطای رند)
متد اندپوینت Toncenter v2 هدف و نحوه استفاده در بک‌اند واحد خروجی نود
GET /getAddressBalance?address={ADDR} استعلام زنده مانده خزانه‌داری TON و تبدیل از واحد nanoTON به کوین گرام جهت نمایش در پنل ریبالانسینگ. nanoTON / 1e9 = GRAM
GET /getTransactions?address={ADDR}&limit=40 دریافت آخرین ۴۰ تراکنش ورودی نود TON به همراه پیام‌های ضمیمه شده (Inbound Messages) جهت تسویه فاکتور. []Transaction (JSON)
PARSER ExtractMemo(in_msg) دیکود خودکار کامنت‌های متنی ساده یا رمزگذاری‌شده Base64 ارسالی توسط کیف‌پول‌هایی مانند Tonkeeper. String (e.g. MEMO-1234)

موتور اشتقاق امن کلیدها و آدرس‌ها (BIP-44 HD Wallet Manager)

پکیج منبع: backend/pkg/hdwallet/hdwallet.go
ماژول hdwallet پیاده‌سازی استاندارد BIP-44 بر پایه کلمات بازیابی مستر (BIP-39 Mnemonic) است. این ماژول وظیفه تولید آدرس‌های ریاضیاتی و مستقل را بر عهده دارد و امنیت سیستم را به حداکثر ممکن می‌رساند.
مسیر اشتقاق دترمینستیک: m/44'/60'/0'/0/{index}
طول کلمات مستر منمونیک: 12 یا 24 کلمه استاندارد BIP-39
سازگاری با متامسک: اندیس ۰ = اکانت ۱ کیف‌پول MetaMask
سیاست ذخیره‌سازی کلید خصوصی: Zero Persistence (هیچ ذخیره‌ای در DB نیست)
تابع ماژول خروجی کارکرد و مکانیزم امنیتی
DeriveAddress(index) آدرس عمومی اتریوم/بایننس (0x...) برای هر فاکتور یا والت مشتری، صرفاً آدرس عمومی محاسبه شده و در دیتابیس ثبت می‌شود. هیچ کلید خصوصی تولید یا نگهداری نمی‌شود.
DerivePrivateKey(index) کلید خصوصی موقت در رم (RAM Only) صرفاً در لحظه‌ای که ادمین دکمه «سوئیپ به خزانه» را کلیک می‌کند، کلید در حافظه موقت رم محاسبه شده، تراکنش امضا می‌شود و بلافاصله از حافظه پاک می‌گردد.

ماتریس پایداری، محدودیت‌ها (Rate Limits) و خطاپذیری سیستم

جدول زیر سیاست‌های فنی مواجهه با خطای شبکه، قطعی احتمالی اینترنت یا اعمال محدودیت نرخ (Rate Limiting) توسط نودهای خارجی را نشان می‌دهد:
سرویس خارجی پروتکل شبکه محدودیت نرخ (Rate Limit) استراتژی مدیریت خطای قطعی یا تاخیر (Fallback Policy)
اوراکل قیمت والکس HTTPS REST ۱۲۰ ریکوئست بر دقیقه به کمک کش ۴۵ ثانیه‌ای، نرخ درخواست‌ها کنترل می‌شود. در صورت قطعی والکس، نرخ‌های اضطراری فال‌بک صادر می‌شوند و صدور فاکتور متوقف نمی‌شود.
نود عمومی BSC DataSeed JSON-RPC HTTPS حدود ۱۰,۰۰۰ درخواست در ساعت در صورت عدم پاسخگویی نود، خطای شبکه لاگ شده و ناظر پس‌زمینه در سیکل ۱۰ ثانیه‌ای بعدی تراکنش را مجدداً پایش می‌کند.
نود شبکه Toncenter v2 HTTPS REST ۱ درخواست در ثانیه (نسخه رایگان) در صورت دریافت کد ۴۲۹ (ترافیک بالا)، ناظر پس‌زمینه بدون ایجاد تداخل، استعلام را به چرخه بعدی موکول می‌کند و هیچ واریزی کاربر مفقود نمی‌گردد.
ناظر تراکنش‌های بک‌اند Go Goroutine چرخه ثابت ۱۰ ثانیه‌ای به صورت کاملاً غیرهمگام (Async) خارج از وب‌سرور اصلی اجرا می‌شود؛ بنابراین افت سرعت نودها هرگز وب‌سایت یا پنل را دچار کندی نمی‌کند.
